## 0.8.1 F-15E 不透明材质

用户提供路径在下划线前多了一个反斜杠；实际模型为 `CoreMods/aircraft/F-15E/Shapes/F-15E_Suite4.EDM`。EDM v10 正常解析：1,500 网格、1,262,341 顶点、1,358,136 三角形、113 材质、126 个参数。初始程序虽返回加载成功，但截图只剩内部结构和灯光；无贴图预览也缺少机身，排除了贴图查找失败。

原文件有 79 个混合模式为 0 的不透明材质，其中许多 `def_material` 保留 `opacityValue=0`。旧 `materialColor` 无条件应用该值，预览无条件丢弃低 Alpha 像素，导出还错误选择 BLEND。依据本机 DCS `Bazar/shaders/model/common/enums.hlsl`、`shader_macroses.hlsl` 及 `functions/diffuse.hlsl` 的模式语义统一修正：模式 0 为 OPAQUE，2 为 MASK/.5，1/3/4/5/6 为通用透明近似；编号仍独立使用 MASK/.1。加法、专用贴花和光照不宣称完全复现。

预览保留原贴图 Alpha 到图片画笔混色结束，之后才决定表面覆盖；未修改贴图文件、画布像素或保存逻辑。新增 226 项回归覆盖全部模式、0/.6 不透明度、GLB/glTF 实际输出、OBJ 共享贴图缓存、FBX 连接及嵌入图片、编号和画布保存重开。RGB 衍生 PNG 的 IHDR 必须为无 Alpha 的 8 位 RGB，包含原 Alpha=0 的彩色像素在内，RGB 逐像素完全一致；原始 RGBA 仍按字节核对。14 组 CTest、32,921 项检查通过。

修复后的默认涂装截图已检查完整机身和机翼。本机模型约 0.44 秒就绪，63 张贴图约 5.58 秒就绪，约 1.04 GiB 驻留，无缺图或纹理警告。两组 GPU 姿态各检查 1,262,341 顶点，最大位置误差 `1.43051e-6 m`。F-100D 的默认涂装及两组 GPU 求值回归也通过，原有玻璃 `__empty__` 占位报告保留。

F-15E 参数 0/9/10/38 的 FBX 数值核对：59,462 项检查、21 姿态、423,654 世界坐标顶点样本通过，最大误差 `7.54648e-7 m`。OBJ 当前组合姿态导出 787 可见网格、1,101,479 三角形和 29 张颜色图片，Blender 完整回读，58 个实际不透明材质均无错误透明连接。整机导出使用全分辨率贴图，未修改 DCS 原始资产。

Blender 4.2 会在未连接 FBX TransparentColor 时仍自动使用 RGBA diffuse 图片的 Alpha；首次实测发现 79 个不透明材质因此被错误接入 Alpha。FBX 现在为这些材质绑定单独缓存的 RGB PNG，同时保留原始 RGBA Video 及来源名称。透明、裁切、编号和 ORM 仍使用原图，避免同源贴图在不同材质之间误用缓存。额外 RGB 资源会增加文件体积，变体数量写入导出报告。

真实 F-15E 的 512 像素画布贴花验收通过：两次分别修改 7,930 / 6,084 像素，用时约 0.519 / 0.313 秒；3 张画布的 GPU 像素、撤销顺序、保存重开、原图比较均通过，相机移动没有额外几何上传或投射深度重建。本轮原始报告和截图保留于本机 `validation/f15e-suite4/`。

最终 0.8.1 的 F-15E FBX 实测：24 个 RGB 变体、1,405,414,336 字节，编码写入约 78.19 秒，无缺失贴图。Blender 4.2.20 回读约 21.24 秒，1,500 网格、1 个骨架、4 个参数片段（拆成 8,720 个对象 Action）、154 个图片数据块均正常；79 个不透明材质的 Alpha 均为常数 1 且无图片连接。最终文件再次通过同一 21 姿态的独立几何核对。原始 RGBA Video 的字节保留、RGB 变体的逐像素一致性由合成回归独立验证。

OBJ 合成测试 294 项通过，覆盖当前姿态、8 权重、逆绑定、镜像绕序、非均匀缩放法线、隐藏部件、编号 UV、绘制 PNG、独立透明遮罩、中文路径及取消/覆盖事务。F-100D 当前姿态导出 993 个可见网格、1,584,976 三角形：不带贴图约 9.37 秒，Panter 涂装约 22.77 秒，28 张颜色 PNG，按需附加透明 PNG。Blender 4.2.20 完整回读，两侧机翼正确解析相邻 Korsan ZIP 的贴图；报告中唯一缺失引用是玻璃材质的 `__empty__` 占位名。

FBX 合成测试使用 ufbx strict 读取及实际动画求值，对照 `Scene::evaluate` / `Scene::transformed`。覆盖独立片段、默认组合姿态、跨 180 度与复合旋转、负缩放、非绑定初始姿态、重复位置不同权重、8 权重、STEP 极窄区间、精确 PNG 字节与双选择器编号。FBX 时钟以每秒 46,186,158,000 tick 表示，边界测试在最近可表示 tick 上求值，并独立断言量化误差不超过半 tick；不放宽几何容差。

整机测试使用每片段起点、1/4、1/2、3/4、终点及初始姿态，按层次及同级顺序映射节点以区分重名网格。F-100D 的 0/9/10/38 参数：21 姿态、533,862 顶点样本，最大误差 `5.31292e-7 m`；F-14 的 0/9/38/1010 参数：21 姿态、262,374 样本，最大误差 `1.08106e-6 m`。该 F-14 没有参数 10，按实际参数列表选择 1010；其快捷编号布局未识别，使用涂装现有编号。

随后对 F-14 全部 221 个参数执行完整核对，0 个跳过：921,461 项检查、1,106 姿态、13,818,364 世界坐标顶点样本通过，最大误差 `2.0786921e-6 m`（容差 `2e-5 m`）。不带贴图的全动画 FBX 为 1,719,339,200 字节，本机导出约 29.41 秒。验证在每段准确起止端点及中间姿态与源场景独立求值比对，修正测试端点浮点运算后新增 [-1.01, 1.5] 边界回归。完整回读约 17 分钟，与导出耗时分开记录；本机原始报告为 `validation/export080/F14-all-animations.verification.json`。

## 调试中解决的问题

- Lua C 库的 longjmp 跨过 C++ include 回调对象，导致错误 require() 访问越界。Lua 改以官方支持的 C++ 模式编译，使用异常展开；回调不吞 Lua 内部异常。
- 原测试只确认配置失败，可能把子进程崩溃当作通过。现检查进程退出码和结构化 Lua 错误，另外覆盖 pcall(require)、深层表和递归栈容量。
- 本机 LLDB 缺少 liblldb.dll，停用该工具。开发调试器只依赖 Windows SDK，不纳入软件发行包。
- GPU 实例索引、镜像三角面、PNG 编码格式、纹理预算分配、异步取消旧任务与 COM 初始化配对均已修正并验证。
