# EDM Studio 0.3.4

直接打开 DCS 的 EDM v8/v10 文件，预览模型与参数动画，导出 GLB / glTF 2.0。Windows 桌面程序，使用本机 GPU 显示模型；不上传文件，不需要运行 DCS 或 Blender。

0.3.4 支持 F-100D 的版本 2 聚光灯节点布局，修复接近文件末尾时出现的字符串索引错误。模型、贴图及参数动画可读取；DCS 专用灯光和效果材质仍按现有边界处理。

0.3.3 修复视口中文操作提示显示为白色碎线的问题。提示使用独立的 Qt 文字层，支持窗口缩放，鼠标操作可穿过文字层继续控制模型。

0.3.2 支持 C-130 使用的版本 1 可见性节点布局，修复 `C-130_lod0.edm` 读取到节点 #8 时的字符串索引错误。

0.3.1 修复 F-14 右翼部分镜像部件被错误剔除、露出内部结构的问题，并改善近距离缩放时的深度精度。预览与 GLB/glTF 导出共用修正后的三角面顺序；之前导出的受影响模型需要重新导出。

## 使用

1. 解压 `EDM-Studio-Windows-x64.zip`，保持整个 `EDM-Studio` 文件夹完整，双击 `EDM-Studio.exe`。
2. 点击 **打开 EDM**，或把文件拖到窗口。也可以把 EDM 拖到 EXE 上。
3. 打开模型后自动扫描涂装。在右侧 **涂装** 下拉框中输入名称搜索并选择，模型会实际显示贴图。可通过 **导入涂装…** 选择 ZIP 或 `description.lua`，也可 **添加扫描目录…**。
   **机身编号** 可为识别到的 NumberNode 模型设置数字（例如 F/A-18 的 408）；**Lua 变量 / 重新求值…** 可输入 JSON 变量并重新读取动态配置。
4. 从左侧选择参数，通过滑块、数值框或“播放”检查动画。可以调节多个参数来组合预览；“归零”恢复涂装的 `custom_args` 默认值，其他参数设为 0。
5. 点击 **导出模型与动画**。使用当前选择的涂装，默认把每个参数分别导出为一个动画片段，名称为 `Argument 000`、`Argument 003` 等。
6. 在 Blender 中通过 **文件 → 导入 → glTF 2.0** 打开 GLB。可以在动画/动作或 NLA 界面切换片段。复杂飞机带有较多层级和骨骼，首次导入可能需要数分钟。

左键旋转、右键或中键平移、滚轮缩放。F / “适应视图”重置视角。Ctrl+O 打开、Ctrl+E 导出。

`samples/animation_demo.edm` 是本项目生成的小型原创测试模型，可用参数 0 测试旋转、参数 40 测试可见性，无需本机 DCS 文件。

## 动画如何保存

- EDM 用参数值驱动动作。GLB 使用时间，因此每个参数导出为独立片段，默认持续 3 秒，可以调整。
- 使用文件里的实际参数范围，包括负值和大于 1 的值。范围写入 `animation.extras` 和同名 `.report.json`。
- 每段动画把其他参数固定在涂装的 `custom_args` 默认值，未设置的参数为 0。当前多个滑块的组合预览不作为独立片段导出。
- 保留平移、旋转、定向缩放、父子层级、蒙皮权重与逆绑定矩阵。四元数按最短弧插值。
- 可见性用标准 glTF 的 STEP 缩放通道表达。蒙皮部件使用带可见性控制的骨骼副本，避免隐藏状态破坏骨骼计算。文件中的辅助节点用于保留变换精度，不宜随意删除。
- 选择“仅导出默认姿态的静态模型”时不包含动画，保留涂装的默认参数。

起落架、舵面和座舱盖的参数编号取决于机型。软件显示文件中的真实编号与关联节点名称，不强行套用其他机型的参数名称。

## 材质和兼容范围

预览与导出共同使用 `description.lua` 的材质映射。支持涂装文件夹和 ZIP、公共/本地贴图、大小写无关匹配以及相对路径。预览使用最长边 2048 像素的贴图；导出保留原始分辨率，将 DDS 等转换为 PNG 嵌入 GLB。RoughMet 的 R/G/B 直接对应 glTF 环境遮蔽、粗糙度、金属度；支持槽 13、EDM 槽 2 中明确标识的 RoughMet 及自动后缀查找。视口使用 GPU GGX 着色，可切换 RoughMet 对比。

自动读取 Windows 的“保存的游戏”实际位置（包括迁移后的路径），发现 `DCS`、`DCS.openbeta`、其他 `DCS*` 配置及其 `Liveries`、用户模组涂装；同时扫描从 EDM 路径、注册表、Steam 库及常见安装位置发现的 DCS 本体。按模型名称及常见机型别名筛选。可手动添加其他目录，选择会保存到本软件设置中。

`description.lua` 支持声明式数据和动态 Lua：函数、循环、条件、运算、字符串/表操作、`dofile` 和本地 `require`。动态脚本在受限 Lua 5.4 子进程中完整求值；出现错误不会套用执行了一半的配置。可注入脚本需要的变量。详情和限制见 [涂装支持说明](docs/涂装支持说明.md)。

NumberNode 编号按模型控制记录和图集 UV 显示，导出保留当前编号；编号动画按 0.1 参数步长转换为标准 STEP 显隐节点，不需要专用插件。手动输入的当前编号参数也作为精确基准保存。印刷在涂装图片里的编号不会自动擦除或替换（本机 F-14B 无 NumberNode）。半透明编号边缘与底色混合、法线贴图、DCS 环境反射/损伤/灯光、其他材质参数动画仍存在差异。碰撞壳不加入可见模型。内部 LOD 保存层级元数据，当前保留所有层级；优先打开明确的单个 LOD 文件。

遇到未知版本、未知节点布局、截断文件或无效引用时会报错，不用扫描猜测的方式跳过坏数据。已验证的机型不代表所有第三方 EDM 变体都得到支持。

- Su-25T：完整读取，多父节点分组及动画通过验证。
- 对 F/A-18C LOD2、F-16C 和 Su-25T 共进行 5,610 次本机 DCS 原生动画函数对照，最大矩阵误差约 `8.66e-6`。

- 独立 EXE 实测读取 F/A-18C LOD2、RTX 5080 预览和 GLB 动画导出成功，输出通过 Khronos 校验。打包已隔离构建机器上的同名 ICU 库，修复 QtCore 启动错误。

- “保存的游戏”中的 F/A-18C Harpia 自定义涂装自动发现并显示，53 个材质已贴图；新增 5 项测试验证涂装配置、路径、像素一致性及默认动画参数。

## 从源码运行

要求 Python 3.12，Windows OpenGL 显卡驱动。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

命令行转换和检查：

```powershell
.\.venv\Scripts\python.exe -m edm_studio "model.edm" --inspect
.\.venv\Scripts\python.exe -m edm_studio "model.edm" -o "model.glb"
.\.venv\Scripts\python.exe -m edm_studio "model.edm" -o "gear.glb" --args 0 3 5 --duration 5
.\.venv\Scripts\python.exe -m edm_studio "model.edm" --list-liveries
.\.venv\Scripts\python.exe -m edm_studio "model.edm" -o "painted.glb" --livery "C:\MyLivery\description.lua"
.\.venv\Scripts\python.exe -m edm_studio "fa-18c_lod2.edm" -o "number408.glb" --livery "C:\MyLivery\description.lua" --bort 408 --args 0 3 5 31 32 442
.\.venv\Scripts\python.exe -m unittest discover -v
```

安装 `requirements-dev.txt` 后运行 `build.ps1` 可以打包 Windows 版本。读取研究工具不属于软件运行依赖；`native_oracle.py` 仅在匹配已核对哈希的 DCS DLL 上用于验证，不附带、不修改或注入 DCS。
