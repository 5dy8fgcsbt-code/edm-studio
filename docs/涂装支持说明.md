# EDM Studio 0.3 涂装与材质支持

修改前的 0.1 代码已先提交到本地 Git：`74a95e3`；0.2 涂装版本为 `04c3a0b`。0.3 继续使用现有 Python / Qt 程序，增加 RoughMet、NumberNode 编号和动态 Lua，未改变 EDM 骨骼动画变换公式。

## 如何使用

打开 EDM 后，程序在后台发现与机型匹配的涂装并载入默认漫反射贴图。右侧“涂装”下拉框支持输入名称搜索；名称后面显示来源，悬停可查看完整路径。选择后同时影响视口和下一次导出。

“导入涂装…”可以选择涂装 ZIP 或文件夹中的 `description.lua`。“添加扫描目录…”可以选择保存的游戏根目录、单个 DCS 配置目录、DCS 安装目录、Liveries 根目录或对应机型目录。额外目录和上次选中的涂装会保存到应用自身的设置中。不会修改游戏或涂装文件。

## 自动发现

- 使用 Windows `FOLDERID_SavedGames` 查询重定向后的实际目录；补充检查用户目录及固定磁盘根目录上常见的 Saved Games / 保存的游戏目录。
- 扫描 `DCS*` 配置中的 `Liveries` 和 `Mods/aircraft/*/Liveries`、`Mods/tech/*/Liveries`。
- 从当前 EDM 所属安装目录、Eagle Dynamics 注册表项、Steam 安装位置和 `libraryfolders.vdf`、常见独立安装位置寻找 DCS。
- 扫描本体 `Bazar/Liveries` 和 `CoreMods`、`Mods` 下模块的 `Liveries`；支持 ZIP 内的配置和贴图，不需要解压到磁盘。
- 使用模型文件名及常见机型别名匹配。例如 `fa-18c_lod2.edm` 对应 `FA-18C_hornet`，`f-16c_bl50.edm` 对应 `F-16C_50`，`f-14b.edm` 对应 `f-14b`。非标准命名模型可手动导入涂装。

Windows 目录 ID 依据 [微软 KNOWNFOLDERID 文档](https://learn.microsoft.com/en-us/windows/win32/shell/knownfolderid)。

## description.lua

```lua
local prefix = "MyPaint_"
livery = {
    {"HB_F14_EXT_01", DIFFUSE, prefix .. "body", false},
    {"HB_F14_EXT_01", NORMAL_MAP, "original_normal", true},
    {"HB_F14_EXT_01", ROUGHNESS_METALLIC, "my_roughmet", false},
}
name = "我的涂装"
countries = {"USA", "CHN"}
custom_args = { [38] = 1, [50] = 0.2 }
```

按第一列的**材质名称**匹配 EDM 材质，不再要求涂装图片与模型默认图片同名。`false` 引用选中涂装自身的图片，`true` 引用模型模块或 DCS 公共贴图库。指定的贴图不存在时记录缺失，不悄悄改用其他涂装的同名文件。支持图片扩展名省略、大小写差异和受限的相对路径。

普通声明式配置使用快速数据读取；出现动态语句时，整个文件交给 Lua 5.4 重新求值。支持函数、循环、条件、运算、字符串与表标准库、`pcall` / `xpcall`、`loadstring`、`_()`、`require('i_18n').translate`。`dofile` / 本地 `require` 可读取同一机型涂装目录内的 `.lua`，或同一 ZIP 中的 Lua 文本，包括有界的 `../shared.lua`。相对路径按当前引用脚本所在目录解释。

右侧 **Lua 变量 / 重新求值…** 接受 JSON 对象，例如 `{"country":"USA","variant":2}`。变量作为全局及 `EDM_STUDIO.country` 等字段提供给脚本；确认会重新读取文件。依赖变量而无法首次导入的配置，可以先设置变量再手动导入。`get_livery_name()` 返回上下文中的 `livery_name`；`current_mod_path` 默认为 `.`，不模拟整个 DCS 插件环境。变量设置在当前窗口会话中使用。

动态求值使用独立进程，Lua 内存限额 32 MiB、指令预算约 50 万、总超时 5 秒。单脚本限 2 MB，最多 64 次引用和 8 MB 引用内容。Lua 不提供 `os`、`io`、系统 `package`、`debug`、协程或 Python 对象；不加载本地二进制模块，不能绕过目录边界。脚本失败、越界、超时都会给出具体错误，不把部分执行结果当作完整涂装。依赖 DCS 运行时 API 或 Lua 5.1 特有环境操作的配置可能仍需调整。实现依据 [Lupa 文档](https://github.com/scoder/lupa)。

`custom_args` 同时用于预览、重置和导出默认姿态。导出每个参数动画时，其他参数固定为涂装默认值；未定义的参数为零。每段动画仍独立播放。

## 显示与导出边界

漫反射槽 0 用于颜色；`ROUGHNESS_METALLIC` 槽 13 用于 RoughMet。优先使用涂装显式覆盖，否则读取 EDM 中的 RoughMet（不少文件存于槽 2），或寻找 `<diffuse>_RoughMet`。普通旧式 Specular 不会直接冒充 RoughMet。显式覆盖缺失时报告缺失，不使用猜测的替代图。

RoughMet 的 R/G/B 分别为环境遮蔽、粗糙度和金属度，与 [glTF 2.0](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html) ORM 布局一致：同一 PNG 绑定 `occlusionTexture` 与 `metallicRoughnessTexture`，金属度/粗糙度系数均为 1，数据通道不做 sRGB 转换。DCS 安装中的 `model/functions/aorms.hlsl` 及 [Heatblur 材质说明](https://f4.manuals.heatblur.se/dcs/modding/liveries.html) 支持该通道定义。GPU 预览使用 GGX 与近似中性环境光，不复现 DCS 天气和环境探针。

NumberNode 保存每顶点编号控制索引（顶点通道 21）；每条控制记录含 U 参数/倍率与 V 参数/倍率。视口按参数计算偏移，使用槽 3 的 DECAL UV 与图集。DCS 的 `vertex_shader.hlsl`、`vt_utils.hlsl`、`decal.hlsl` 明确采用该流程；本机 `UniModelDesc!NumberNode::getHandles` 也确认记录中的两个整数是参数编号。参数 -1 表示该方向无控制。

**机身编号** 输入框支持已识别的常用编号布局。实测 F/A-18 从左到右为参数 442、31、32，输入 408 即 0.4、0.0、0.8。所有实际编号参数也显示在左侧列表，可手动调节。模型没有 NumberNode 时禁用快捷输入，不修改印刷在涂装图中的编号；本机 F-14B 属于这种情况。

GLB/glTF 静态姿态保留当前编号的精确 UV；选中编号参数导出动画时，将 0.1 参数步长上的图集状态变成标准 STEP 显隐节点，常见编号从 0 到 9 可直接播放，不依赖自定义着色插件。其他动画片段恢复所选编号。编号面使用 alpha cutoff 0.1 与微小法线偏移。**连续 UV 滚动及半透明字形与底色的精确混合不等价**；非十进制布局可手动设置当前参数并静态导出，但自动片段仍采用 0.1 步长。法线贴图、其他材质参数动画和 DCS 专用光效继续保留元数据。

`countries` 作为元数据保留，不限制本工具选择涂装。

预览纹理最长边限制为 2048；导出使用原始分辨率。两者共享同一套材质及资源匹配逻辑。导出的 `.report.json` 含涂装配置、实际图片来源、缺失贴图和解析提示。完整飞机的高分辨率贴图会使 GLB 显著增大。

## 本机验证

- DCS 本体中的 F-14B VF-103 官方 ZIP：实际 GPU 预览成功，包含起落架和座舱盖动作；导出 132 个带贴图材质及 4 个动作，Khronos 校验 0 error / 0 warning。
- 位于 `E:\9950XSavedGames\DCS\Liveries` 的 F/A-18C Harpia 自定义涂装：由扫描发现，53 个材质显示贴图。
- 0.3 F/A-18 实测：RoughMet 28 个材质，15 组编号网格；界面分别显示 408 和 123。7 个参数动画 GLB 通过 Khronos 校验（0 错误、0 警告）；Blender 5.2.1 成功导入 7 个动作，顶点移动 2.152 米。
- 19 项测试覆盖原始动画、发现目录、纹理像素、动态 Lua 函数/循环/引用/上下文、超时/内存/目录边界以及从导出二进制独立采样的编号 UV 和片段基准状态。

本机有多个 DCS 安装和旧配置，列表保留不同来源的同名涂装；具体数量随文件内容变化。
