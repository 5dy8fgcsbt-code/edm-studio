# 无人值守开发记录

## 0.12.0 微小缝隙选项与本轮问题

清晰度修复验证后已先独立提交 `a33c3c6`。随后增加可选跨缝，27组回归和F-100D/F-15E真实GUI全过程通过，再单独提交本功能。子代理分别实现独立跨缝内核/116项回归，以及清晰度原因审查/52项回归；主代理整合界面、缓存、实际验证、文档和软件包。

本轮处理的其他问题：

1. 将近邻边界直接焊接会丢失缝宽、挤压图案，完整端点匹配又会遗漏不同细分。现在用边界重叠区间建立临时连接，保留缺失条带的距离；略斜缝隙使用方向传输，保留原三角面长度和朝向。
2. 仅凭距离可能误连重叠蒙皮、背面或外挂。增加相对边界、局部切面、所属外挂实例和歧义过滤；匹配采用局部空间索引，有数量、时间及取消限制，关闭选项不运行新增匹配。
3. 普通几何接缝容差可能放宽用户输入的实际缝宽。跨缝使用独立浮点容差，测试确认1.99mm不能跨2mm，而2mm能容纳顶点浮点舍入。明显台阶、锐折面和不确定邻接仍会停止。
4. 缝宽或开关变化必须重建局部坐标。现在都包含于缓存键和核心校验中；GUI验证关闭、更改和恢复参数的行为，预览和最终写入共用同一个不可变曲面坐标。
5. 保留原图默认8K会让缺失底图的空白回退无谓变大。两个自动绘制入口的无源空白改为最高2048，与原单材质入口一致；有源贴图仍按原尺寸，刻意透明贴图也保持原样。8K图层依然比2K占用更多内存，编辑像素预算为2GiB，加载临时副本不计作进程硬上限。
6. 为便于找到功能，跨缝复选框放在模式选择下方，默认关闭，旁边可直接调整0.1–20mm（启用默认2mm）。清晰度详细信息收入可展开的「落点清晰度」，保留画布质量选择。

限制：不会填补模型几何或给空缝生成像素，不跨不同外挂实例；匹配基于几何条件，不识别机械部件语义。旧低分辨率工程不能自动恢复已丢失细节；小UV区域仍限制可用像素。真实F-100D诊断的固定落点没有合格的缺失间隙，开关和完整GUI流程在那里验证，跨缝后的连续图像由合成模型像素回归验证。详见[验证记录](NATIVE_VALIDATION.md)和[曲面贴花说明](SURFACE_CONFORMING_DECALS.md)。无新增第三方依赖，无游戏资源进入分发包。

## 0.11.1 贴花清晰度修复

默认新画布上限2048会在首次绘制时降低原始底图分辨率，浮动贴花则直接采样原图片，造成盖印后变糊。默认改为保留原图尺寸，最高8192，小图不放大；低内存选项仍保留。贴花面板显示实际/预计画布尺寸和局部UV像素估计，不在渲染线程重新读取游戏贴图。已有低分辨率工程保留原像素与历史，不能凭改选项恢复此前丢失的细节，需要从原涂装重新绘制。

26组回归和F-100D真实GUI全过程通过。合成DDS按mip使用不同颜色，直接检测错误降采样；实际首次盖印另验证撤销后底图与源文件逐字节相同。测试构建时发现Windows头文件的 `near` / `small` 宏与测试局部名称冲突，已重命名；诊断入口的2K校验也同步扩展到默认值及4K/8K。没有新增依赖或修改DCS文件。

用户要求：调试后先提交本地 Git；之后新增动画部件识别、模板及直接画笔、图片环绕贴附、当前相机投影。每项测试完成后单独提交，不向远程推送。

## 0.11.0 曲面贴花

按“主要让贴花更好地贴合模型”的目标，新增默认「曲面贴合」模式。以鼠标落点为起点，沿原始网格连接及吻合的材质接缝建立局部曲面坐标，预览与盖印共用；仍按各自原始 UV 写入当前层，导出保留原模型结构。「平面投射」和相机投影保留。三个子代理分别处理映射内核、独立回归、GPU 预览；主代理整合异步交互、界面、实际机型检查、文档及打包。

本轮发现并处理的问题：

1. GPU 预览使用独立缩小的图片并只读最高分辨率像素，细字与实际烘焙过滤不一致。图片画笔改用与 CPU 相同的解码像素，曲面预览按屏幕像素覆盖范围采样，并保持先合成、后过滤的颜色顺序。
2. GPU 遮挡的相邻采样可能落到同一机身的不同小三角面，产生绿色孔洞。增加受投影像素大小限制的容差，保留最终写入时的精确射线。修正后 F-100D 预览/盖印对比从平均通道差 27.17 降到约 9.63，通过原定阈值。
3. F-100D 翼面存在位置完全重合、索引独立、朝向相反的两层表面。只按位置连接会错误判成非流形，而拾取背面又会使全部样本被过滤。现在优先沿原始索引连接，同位置拾取优先选择朝向观察点的面，真正双面表面使用统一方向修正。原点击处由仅 1 个三角面、0 像素变为 51 个三角面、约 20,629 像素；机翼预览与盖印单独比较通过。
4. 仅使用指针判断缓存，不能可靠识别在原地址替换姿态的情况。为 PaintSurface 增加唯一代次，旧曲面坐标会被拒绝；另验证了种子不动但邻近遮挡物改变的情况。
5. 图层面板展开时遮住图片画笔的重要控件。进入贴花工具时先折叠图层管理，保留当前层提示，加载、盖印与模式切换更容易找到。悬停计算在后台运行，计算未完成时点击仍会捕获准确落点；隐藏原始视图中的无用计算会取消。

25 组 CTest 和 113 项曲面专项检查通过。F-100D、F-15E 的机身与机翼两次盖印、逐字节 GPU 读回、撤销重做、原图对照及工程保存重开全部通过，旧平面模式也通过实际回归。完整指标见[原生验证](NATIVE_VALIDATION.md)。游戏模型及图片只在本机验证目录中使用，不随源码或软件包分发。

第一版仍有明确范围：真实裂缝、T 形不匹配边界和无法一致展开的强曲率区域会停止延伸；共用 UV 仍会联动，没有重新布局 UV 或自动填充岛边缘。GPU 预览边缘保留有限过滤/遮挡误差。贴花盖印后是图层像素，调整位置需撤销再盖印。使用说明见[曲面贴花](SURFACE_CONFORMING_DECALS.md)。

## 0.10.0 涂装图层

已加入跨材质统一图层：新建、重命名、显示、不透明度、透明遮罩、上下排序、复制、删除、清空、撤销与重做。画笔、贴花、相机投影和模板写入当前层，底图保留；v3 工程保存完整分层，DCS/模型导出使用可见层合成结果。三个子代理分别承担稀疏内核、工程持久化和真实 GUI 诊断，主代理集成界面、异步绘制、模板、外挂及打包。

本轮发现并处理的问题：

- 原画布是平面图像，简单增加列表不能恢复下层内容。现在底图独立保存，每层按 64×64 块存像素，复制层使用写时复制；GPU 使用局部更新后的合成图。
- 后来首次触及的材质不在之前的建层撤销组中，卸载外挂又会重排材质。加入独立图层控制画布作为全局状态来源，历史重映射保留它，撤销后再同步各画布。真实武器组合验证了索引前移和层内容保留。
- 旧模板直接替换整个画布并清历史。改为在同一事务中替换当前层，保留底图、其他层和待用模板的取消状态；大模板的缩放/放置在线程中完成。
- 分层工程即使当前合成图相同，隐藏层仍可能不同。只按完整共享记录和实际材质别名复用画布，独立外挂实例保持独立；保存每块 SHA-256，加载后重新合成校验。
- v2 平面工程迁移会额外生成底图副本，共享层又可能在保存时展开。加入迁移、全局提交及全局快照的 2 GiB 预算预检；副本在复制像素之前先核算。内核每像素预算查询曾会遍历历史，已改为常数时间计数及新块检查。
- 静态审查发现工程重开会对已分层的控制画布重复初始化，改为先准备新的控制画布再发布。首轮编译发现 `shared_ptr::unique()` 在当前 C++20 工具链不可用，改为单写线程下的 `use_count()` 检查。
- 初版界面三层列表会裁掉第三行，已改为紧凑行高及随层数变化的列表高度，实际 1720×1080 截图验证无裁切。
- 补测启动命令的 PowerShell 数组拼接引入目录首尾空格，错误报告再写入无效目录触发二次异常。改正诊断启动方式，并保护顶层错误报告；无效目录现在正常退出 1，正常贴花验证退出 0。

验证：24 组 CTest / 35,176 项计数检查全部通过；F-100D 201 项图层检查，LAU-88 + AGM/AIM 137 项，另完成实际自动绘制、模板取消/撤销、完整工程 UI 保存重开、两次 2K 表面贴花和 GPU 核对。数量、耗时和产物路径见 [原生验证记录](NATIVE_VALIDATION.md)。

保留边界：这是像素图层，贴花在盖印前调整位置/旋转/大小，盖印后不作为可拖动对象保留；PSD 图层、文字对象、蒙版和特殊混合模式未包含。连续覆盖满幅 8K 模板时，保留撤销所需的瞬时像素可能先达到 2 GiB，操作会完整回滚；保存并重开可释放会话历史。F-100D 玻璃材质三个原有 `__empty__` 占位仍记作缺图，该完整导出工程标记 `self_contained=false`，已编辑图层及 Lua 本地引用均通过验证。没有新增第三方运行库或改写游戏文件。

0.6.0追加要求：三种绘制工具自动定位贴图，取消手动选择材质和预先建立画布的使用门槛；连续笔迹与图片应用均可跨材质，作为一次操作统一撤销。

## 0.9.2 碰撞壳体支持

原解析器读取 ShellNode 后只累计数量，丢弃父节点、自有顶点格式和网格数据；因此用户提供的 FA-18C 独立碰撞 EDM 报没有可导出三角网格。现单独保留壳体，在文件没有外观三角网格时构建双面、有区分颜色的可见壳体，沿用已验证的父节点动画与显隐。普通外观 EDM 仍只生成外观网格。

本轮处理的问题与边界：

- ShellNode 顶点布局独立于外观材质，不能用原材质索引解释。现使用每个壳体自身的格式，校验父节点、索引、长度与有限浮点值，缺法线时计算法线。
- 碰撞壳没有涂装 UV，不能冒充可绘制表面。纯碰撞场景标注类型并跳过涂装扫描和贴图加载，绘制面板解释原因，保留动画和模型导出。
- 文件还含 52 组 SegmentsNode 碰撞线段。此次只支持 ShellNode 三角壳体；模型信息明确提示未转换的线段，未伪造管状三角网格替代它们。
- 同名碰撞壳不能依靠名称做验证映射。真实文件回读使用原壳体索引；FA-18C 中一个未引用顶点被正常压紧，OBJ 中一个零面积三角按既有规则过滤，均已与原始数据逐项核对。
- 新增普通外观回归最初错误复用了仅碰撞壳存在的参数 38，触发“Unknown export argument”。修正独立测试的导出配置后，128 项检查通过，未放宽产品对无效参数的校验。
- 真实 FBX 验证脚本首次误找独立 `.report.json`；单体 FBX 的报告在 CLI 标准输出，改读该实际路径后通过。属于验证脚本问题。

最终 22 组回归 / 34,962 项检查通过，两种真实 FA-18C 碰撞文件均完成 GLB/glTF/OBJ/FBX 输出和独立动画核对。无新增运行库、无游戏资源改写。详细数量与误差见 [验证记录](NATIVE_VALIDATION.md)。

## 0.9.1 点选后显示卸载按钮

交互按用户补充调整：点黄色连接点只弹出菜单，在旁边按“卸载”才移除。菜单沿用暗色界面，显示连接点名称和琥珀色按钮，空白处或 Esc 收起。Pylon 与 Point 使用同一处理方式；挂架卸载会级联移除下级武器。

本轮处理的问题：

- 删除中间物体会改变后续节点、材质与网格索引。加入完整映射，同时更新蒙皮、原始节点索引、统计和绘制别名；只复制保留网格，避免复制马上丢弃的大模型。
- 画布和撤销记录不能保留旧材质号。历史按共享画布身份过滤、重映射，剩余 undo/redo token 保持不变；共享组只处理一次，分配失败时保留原历史。
- 重映射发布后若再分配状态字符串，失败会留下绘制场景与 GPU 场景不一致。审查发现后，改为提交前准备字符串与校验，提交后只交换所有权和清理缓存。
- 卸载后的参数编号存在空洞，工程重开不能重新连续编号。恢复流程使用保存的严格参数映射，并验证完整覆盖、唯一性和无冲突；完整工程身份验证保留。
- 只隐藏或清理几何会遗留贴图驻留和绘制遮挡。现在同时压紧材质绑定、释放无引用 GPU 贴图、重建绘制表面，导出只含剩余物体。
- 用户可能在卸载物体前已绘制。若有画布，后台先保存卸载前的 PNG 恢复工程，再发布新模型；恢复失败时不卸载。实际移除后的恢复画布逐像素回读通过。

Release x64 构建与 21 组回归通过；真实 LAU-88 的武器单独卸载、F-15E 的挂架级联卸载、剩余涂装和工程重开、已卸载画布恢复均通过。完整数据见 [验证记录](NATIVE_VALIDATION.md)。无新增依赖，未改写游戏资源。

## 0.9.0 挂点与外挂

已完成下方“显示挂点”“显示外挂物体”复选框、点击 Connector 加载 EDM、AttachPoint 自动对齐、Pylon/Point 逐级连接、外挂独立动画参数、机体与外挂自动绘制、隐藏后的绘制穿透、统一 Lua/DDS/RoughMet 导出，以及组合绘制工程自动恢复。新增功能沿用 C++/ImGui/D3D11 与现有依赖，无新增运行库。

处理的问题：

- AIM-120C 的 UTF-8 材质名曾被 CP1251 解码，导致统一 description.lua 的名称不匹配。解析器现在优先接受严格有效的 UTF-8，否则回退 CP1251，v8/v10 都有回归。
- 同名贴图分属不同 EDM 时可能误取主机资源。现在按各材质源 EDM 缓存独立解析器；实际组合贴图无缺失，DDS 内容逐字节核验。
- 追加场景可能重置画布、撤销或旧工程的独立材质别名。现在保留旧材质索引和别名前缀，只重建绘制表面；实际编辑后追加外挂验证通过。
- 可见性开关如果只改渲染，会留下不可见遮挡。现在同时排除 GPU draw 与 PaintSurface BVH；画笔、贴花、相机投影的拾取与遮挡测试通过。
- 外挂同号动画参数会与主机相互影响。现在独立重编号，默认值、编号图集和导出元数据同步；GLB/FBX 19 姿态独立回读通过。
- 第一次自动画笔诊断用整架飞机的尺度给小导弹设置笔刷，触发 UV 栅格预算保护。诊断改为根据目标材质尺寸选择测试笔刷；生产绘制预算和保护保持不变，实际写入/撤销/GPU 回读通过。
- 新测试中的函数名 `near` 与 Windows 宏冲突，已改名。最终全量构建与 19 组回归通过。

使用边界：单个 DCS description.lua 按材质名寻址，多件同名材质若绘制不同内容无法分别表示，导出会明确指出冲突；无 AttachPoint 按原点连接并提示，多 AttachPoint 拒绝歧义。手工挂接不限制游戏允许武器列表。模型内部多级 LOD 仍沿用已有“全部保留”的行为，相关模型会显示警告。源 EDM 不复制进绘制工程，重开组合时需要原文件仍可访问。

## 0.8.1 F-15E 材质兼容

测试用户指定 F-15E 时，解析和贴图查找均成功，但截图暴露机身不可见。根因是不透明材质中遗留的 `opacityValue=0` 被当成实际透明度。统一修正预览及导出对不透明、裁切、透明模式的判断，同时补上模式 5/6；保留编号的独立透明裁切，原始画布 Alpha 继续参与图片画笔混色。

独立 Blender 回读又发现其 FBX 导入器会自动把 RGBA 图片接到 Alpha，不能仅靠不连接 TransparentColor 解决。因此 FBX 增加无 Alpha 的 RGB 贴图变体，保留原图和来源关系；逐像素测试确保 Alpha=0 下的颜色不丢失。此兼容措施增加导出体积，4 GB 上限仍适用。模式 3 加法和 DCS 专用效果仍是通用材质近似。

新增测试和真实模型验收涵盖机身显示、动画、OBJ/FBX、贴花、撤销及工程重开，详见[验证记录](NATIVE_VALIDATION.md)。本轮未改写游戏文件。

## 0.8.0 OBJ / FBX 导出

采用原生 C++ 写入，OBJ 固定当前姿态，FBX 保留层次、蒙皮与每参数动画。调研发现直接转用现成 FBX 导出路径会丢失恒定插值、连续旋转和部分绑定语义，因此复用本项目已验证的场景构建数据，独立编写二进制序列化；新增的 MIT ufbx 只作为测试读取器。

本轮处理的兼容问题包括：Windows `near` 宏与测试辅助函数重名；JSON 数组索引类型；FBX 整数属性标记和动画对象类型名；Blender 忽略指定 UVSet，导致编号误用普通 UV；中间骨骼节点被拆成多个骨架、非恒等网格的绑定参照；默认隐藏的可见性祖先不能作为退化的骨骼绑定姿态。保存窗口使用所选扩展名，OBJ 模式自动禁用动画设置；导出主按钮放在选项下方，避免被长说明挤出可视区域。取消时等待旧导出工作结束，防止紧接着发起同路径导出。

极窄 STEP 测试曾在精确数学时间与最近 FBX tick 间相差约 5 皮秒，现分别保留原时间与可表示时间进行严格核对。另一个限制来自 Blender 4.2：它将所有 FBX 曲线按线性读取并合并过近的帧；兼容保持帧能处理普通切换，但极短显隐脉冲可能丢失，不能替代标准 CONSTANT 支持。

全参数核对还发现测试端点的浮点运算问题：F-14 参数 114 的范围为 [-1.01, 1.5]，用最小值加完整跨度会得到 1.4999999999999998，恰好仍在显隐切换之前。验证程序现直接使用准确的区间端点，并新增边界回归；导出文件本身的终点和显隐轨迹正确，未为通过测试而改变动画。

OBJ 的 MTL 和图片需要一起移动；安全覆盖会保留旧的唯一命名附属目录。FBX 7.4 文件上限 4 GB，ORM 通道通常需接收软件手动连接。真实 F-100D 的 `__empty__` 占位与 F-14 的 5 个角色共享贴图引用会显示在缺图报告中，不伪造已找到贴图。原始游戏资产和所有整机导出结果均不纳入 Git 或安装包。验证细节见 [原生验证记录](NATIVE_VALIDATION.md)。

## 0.7.1 F-100D 白色机翼修复

Panter 涂装的机翼使用 `../113Filo 'Korsan' (Pirate) Eskisehir AB 1964/...` 引用另一个 ZIP 涂装中的贴图。旧加载器只处理当前 ZIP 与实际文件夹，未把相邻 ZIP 作为同名目录解析，因而使用缺图时的白色显示。现在按明确的相对路径解析跨 ZIP 资源，预览、绘图基础贴图和导出共用该解析器；无需解压或修改游戏涂装。

本轮发现并处理的问题：

1. 相邻 ZIP 对应的虚拟目录并不存在，先调用 Windows 路径规范化检查会产生访问错误并阻断 ZIP 回退。改为先确认实际目录存在，再检查其物理路径；ZIP 按自己的实际文件路径检查。
2. 只按文件名搜索会误选其他涂装中的同名机翼，且可能覆盖当前 ZIP 内嵌套引用的原意。改为匹配完整虚拟路径，优先当前 ZIP 内的引用及明确指定的散装目录，不扫描无关涂装。
3. 跨目录支持需保持原有范围约束。资源路径限定在当前机型的涂装父目录，拒绝绝对路径与越界路径，并过滤 ZIP 内无效路径。测试读取实际 DDS 字节，包含同名干扰、默认贴图存在但显式资源缺失等情况。
4. 测试夹具最初包含 miniz 本身拒绝写入的绝对 ZIP 条目，已移除该不可构造条目；保留可构造的父目录越界 ZIP 条目，以及绝对、UNC、盘符资源引用检查。

新增 173 项贴图解析检查通过，全部 11 组、1321 项回归通过。实际 Panter 涂装的 14 条跨 ZIP 缺图记录全部消失，左右机翼图案恢复；两条既有玻璃 `__empty__` 记录仍在报告中。相同涂装的 GLB 导出包含 71 张图片、两个动画，机翼颜色和 RoughMet 的四项绑定核对正确，Khronos 校验 0 错误、0 警告。具体文件与结果见 [原生验证记录](NATIVE_VALIDATION.md)。所有游戏资产及验证产物保留在本机，不纳入发行包。

## 实现中的判断

- 部件名称属于推断，必须给出移动区域和置信度，保留不确定结果；不把参数编号硬编码成机型通用名称。
- 几何分析可能需要显示被其他参数隐藏的网格，分析使用的姿态单独记录，不能改变用户预览和导出姿态。
- 涂装编辑使用副本与撤销记录，保存到用户选择的位置。原 DCS 贴图和模板保持原样。
- UV 重叠会让同一纹素影响多个表面，软件需明确说明这种模型固有限制。
- 图片投影应检查被其他表面遮挡的区域，避免把相机前方图片错误穿透到背面。

## 最后复查发现的问题

1. 画笔的12ms预算停止采样后直接跳到鼠标终点，快速拖动可能漏笔。改为保留每段拐点和尾段的跨帧采样队列；松开后继续处理，完成后才结束一次撤销记录。31项队列测试覆盖快移、预算暂停、待处理状态追加拐点、释放排空、取消及队列上限。
2. 工程加载只计算去重PNG的内存，而UI会为各材质展开独立画布。现按展开后的总RGBA计入1GiB预算，并严格限制单边8192。用小预算测试复现并确认共享PNG不能绕过检查。
3. 打开工程原来只恢复绘制图片，可能丢掉基础涂装、RoughMet和custom_args。新增完整外观加载，常规工程使用自己的description.lua及依赖目录；恢复工程保存已求值涂装快照，不重新执行原动态Lua。工程检查从60项增至75项，包含重新打开再保存后RoughMet字节、参数、国家列表均保留；旧恢复文件兼容，缺失外部资源明确警告。
4. 根目录旧build.ps1仍指向PyInstaller。现默认构建、测试、打包C++程序；旧构建入口移至明确标记的tools/build-legacy.ps1。Windows包从全新暂存目录构建，避免把本机用户恢复工程或设置打入ZIP；版本目录和最新ZIP别名一起更新。
5. 自动诊断180秒超时原来可能仍返回成功退出码，现设置错误并返回非零；最终流程约26秒就绪，未触发超时。
6. 打开工程时旧的异步涂装求值可能晚完成并覆盖恢复外观，现先取消旧livery任务，并恢复对应JSON上下文。工程外观事件尚未应用时暂缓拾取结构重建，避免先按旧姿态重复构建。
7. 发行源码ZIP必须来自已提交的HEAD，打包脚本现拒绝有未提交内容的源码发行，并检查HEAD与EXE版本；包内记录源码提交。正式EXE写入Windows版本资源，避免旧程序混入新版本包。

## 0.6.0自动绘制改造

“浏览 / 直接画笔 / 图片环绕 / 相机投影”始终显示。画笔按模型落点异步匹配当前涂装的漫反射资源并创建所需画布，一笔可跨多个材质。环绕和投影按同一个全局放置范围自动处理多张贴图，整次操作统一撤销、重做或取消。动态编号图集排除在绘画之外，原编号设置继续使用。

新画布分辨率上限默认2K，可选择4K或8K；改变设置不重采样已有画布。预载模板在下一次落笔时绑定目标，替换整张漫反射画布；有未保存编辑时，先写恢复备份。完整工程PNG、DDS、description.lua保存，以及当前绘制结果的GLB导出流程保留。

本轮发现并处理的问题：

1. 旧界面把工具入口放在“已有画布”条件内部，首次打开模型时用户看不到直接绘制入口。工具选择移到画布条件外，首次落笔即可启动资源匹配。
2. 原画笔、环绕和投影只接受一个手动选择的材质。画笔改为按世界空间落点跨材质匹配；图片映射先计算全局覆盖候选，再使用同一放置参数写入各张画布，不能为每个材质重新适配图案。
3. DCS同名、同漫反射资源的材质可能是别名。若分别调用映射，会在同一UV纹素上多次混合半透明图片。别名共用画布，映射一次接收全部对应材质ID，并共用“已写入纹素”记录；共享UV联动仍然保留。
4. 多画布处理中，后一个材质失败不能留下前几个材质的修改。新增跨画布事务，先准备全部历史记录，再统一提交；取消、异常和预算不足由外层回滚所有已触及画布。撤销/重做同样作为一个批次处理。
5. 保守覆盖候选可能完全被遮挡，或图案透明度使它没有实际改动。为这种候选读取的新2K画布不能作为有效覆盖保留下来，否则未绘制区域也会被无意降采样。没有像素变化的临时画布需释放，原贴图继续使用。
6. 异步读取贴图期间，鼠标已经继续移动。仅保存最后落点会丢失笔迹和转折；轨迹需要排队，贴图就绪后继续处理，松开鼠标后也要排空再结束这一笔。
7. 顶点都在图案外的长三角形仍可能穿过图案，跨近裁剪面的三角形也不能先做透视除法后简单丢弃。投影使用齐次多边形裁剪，圆柱使用轴向裁剪和角域裁剪；超过180°的角域按两个凸区域的并集计算，避免选中相反扇区。
8. 为每个材质重新分配120秒会让整次自动映射耗时失控。跨材质操作共用墙钟、像素和射线预算，候选扫描及贴图加载也计入墙钟时间，超限时整组回滚。
9. 多材质映射原先每张画布重复扫描整机。候选扫描现保留原始三角面ID，各画布直接复用其覆盖列表；新旧路径逐像素对照一致。没有变化的材质不再逐条弹出警告，重复UV提示合并到折叠的操作详情。
10. 小笔刷碰到细长面时，按无限平面估算UV范围可能扫描整张贴图。改为先用世界空间笔刷范围裁剪三角形，再界定UV扫描区域；最终仍用原三角形重心坐标及精确球形/遮挡判断。真正覆盖过多密集面时保留采样预算与整笔回滚，用户需缩小笔刷。
11. 模板替换了贴图，但零透明度笔刷没有修改像素时，旧保存判断可能误认为没有编辑。模板安装本身现在标记未保存；真实GUI验证其快照、恢复工程和GPU像素，随后重开原工程保持一致。
12. 后台操作刚提交而窗口关闭时，普通完成回调可能被取消。新画布在工作线程结束后由必定执行的清理步骤发布，已提交结果可以进入关闭恢复；尚未提交的操作整组回滚。贴图首次解码时取消整笔也验证了画布、轨迹、历史和保存状态均恢复。
13. 2K投影串行逐张进行遮挡计算，在F14默认范围也触发120秒上限。改成最多4张独立画布并行：先准备一组的画布和历史，再启动线程，全部结束后才准备下一组。历史准备失败可能自动回滚，因此不能和仍在写入的线程同时进行。取消先等待所有线程停止再统一回滚；GUI诊断在真实映射线程运行时发出取消，核对全部原像素、GPU和旧撤销记录。
14. 临时画布释放后分配器可能复用相同地址，不能只用指针地址判断“同一画布被重复调度”。使用共享对象的所有权身份去重；最终验收前冻结源码并强制重新编译，避免并行开发中的文件修改时序让增量构建保留旧实现。
15. 精细模式下有效烘焙超过两分钟并不代表程序失去响应。最终将2K及以上的整次时间预算设为300秒，较低精度仍为120秒，内存与总采样保护保留。后台烘焙期间测试使用正常交互刷新率，完成后才进行不限制帧率的相机基准，避免测试自身争抢资源；这项预算调整与算法提速分别记录，不把延长等待写成性能提升。

验证状态：9组原生测试、1082项检查通过；自动映射74项检查通过，覆盖不同分辨率画布的边界连续性、近裁剪与长边穿框、圆柱宽角与角度缝隙、外部统一取消、跨材质遮挡、别名透明度只混合一次、总预算。另用96个可复现的随机三角形，将候选结果与实际逐纹素应用对照，未漏掉产生像素变化的材质。既有环绕20项、投影23项回归通过。跨画布事务与局部笔刷146项、轨迹38项通过；包含分配失败注入、真实细长三角形及逐像素参考对照。

真实模型候选扫描已完成：F14约116万三角形，投影扫描0.155秒、窄环绕0.056秒；F100约158万三角形，分别0.204秒和0.081秒。这些仅验证覆盖识别和扫描耗时，不代表完整贴图加载、图片烘焙或GUI流程耗时。F14/F100的自动绘制GUI测试已完成，分辨率、覆盖范围、每项像素及耗时详见NATIVE_VALIDATION.md。F100的画笔、环绕、投影、取消首次加载、模板零像素保存和恢复工程全链通过；前文0.5.0的单画布结果与本轮结果分别保留。

为避免遗漏细小可见区域，候选识别只作保守几何过滤，不用几条采样射线断言整个材质不可见。因此候选列表可能保留最终完全遮挡的材质；真正遮挡仍逐纹素判断，无改动的候选不发布为贴图覆盖。

最终发行二进制的F14默认2K与F100的512精度全链验收均通过：分别重开30张和20张画布，像素及GPU一致；两者都验证了4个映射线程运行时取消后的完整回滚。F14大范围2K投影实测239.07秒、环绕13.05秒，仍是耗时较长的后台烘焙；F100对应测试为8.82秒和1.13秒。F14完成后相机基准中位数0.4854ms、P95 0.8506ms，0次模型几何上传。完整测试配置、首次失败与修复后的结果均记录在验证文档中。

## 0.7.0 真正的表面贴花 / 图片画笔

用户进一步确认需要改变操作功能。原“图片环绕”曾被误解为圆柱包裹，0.6.1仅改名没有满足这个交互；0.7.0将“贴花”实际替换为按鼠标落点和表面法线的局部正交投射。加载图片、移动鼠标看表面预览、左键单击盖印，自动写入所有覆盖到的漫反射贴图。支持大小、锁定比例、旋转、不透明度与贴合深度，相机投影继续独立保留。

本轮处理的问题和设计决定：

1. 仅叠加屏幕图片不能表现图案在曲面上的位置。新增GPU表面预览，在模型片元中用世界坐标采样图案、再参与原光照；预览不修改画布，正式盖印才烘焙到UV。
2. 局部投射必须限制厚度并避免穿入背面。新增有限投射盒、背面筛选、从完整模型前方发出的平行遮挡射线。盒外前景部件也能遮挡，编号图集不参与绘制或遮挡。
3. 很小的贴花落在细长三角面上仍可能产生巨大UV扫描。先裁剪实际三角形与投射盒，再限制UV光栅范围；最终保留原三角重心插值，和完整参考逐字节对照。
4. 实时遮挡不能逐帧重建模型。GPU深度图按贴花位置、模型和动画姿态缓存，相机移动复用；深度通道沿用已有几何及蒙皮缓冲，姿态包围盒按网格/骨骼保守计算，不逐帧变换全部顶点。
5. 半透明材质上的预览需要保留材质自身透明度。贴花按CPU相同的sRGB/alpha规则合成，取消保留遮罩时仍乘材质alpha，避免预览把舱盖等表面变得不透明。可绘制UV标记与动画高亮使用不同位，互不覆盖；编号和无UV表面被排除。
6. 已盖印的图片再叠一层悬浮预览会显得颜色加深。完成盖印后隐藏当前位置预览，鼠标移动或调整参数后再显示。鼠标落空会清除位置，动画姿态改变时旧落点失效，避免在旧姿态位置误盖。
7. 一次点击采用一个跨贴图历史步骤，后台解码、多个画布的烘焙、取消回滚和保存恢复继续使用既有事务。默认单击盖一次，不因按住鼠标重复盖印；这也避免高分辨率图片产生无意的多次透明度叠加。

最终10组、1148项检查通过。F14/F100的2K真实GUI验收均从零画布开始，确认预览未修改贴图、相机旋转不重建几何或投射深度图、两次盖印撤销顺序、最终GPU像素和完整工程重开；两模型各重开4张编辑画布。局部盖印实测0.115～0.947秒，范围与像素数见NATIVE_VALIDATION.md。修改shader后两模型GPU动画顶点回读也全部通过。

预览遮挡精度受2048²深度图限制，最终写入以精确射线为准；共享UV仍会联动。旧圆柱代码保留供旧诊断与核心回归使用，界面贴花已不使用圆柱定位。

## 使用边界和处理决定

- 识别结果使用实际顶点位置、蒙皮运动、区域形状及节点名称共同推断。F14后部机翼与平尾、细小面片与座舱盖容易混淆，已调整规则并加关键部件检查；未确定的参数不强行分类。
- 保留原模型的重叠UV与内部LOD，不擅自改动模型拓扑。共享UV不能给共享纹素的部件独立上色；单独LOD文件更适合直接查看。
- DCS专用着色器、灯光、损伤效果和部分材质动画无法完整映射到通用PBR。法线/反射效果与DCS画面可能有差异；几何动画、层级、显隐和编号状态经过独立回读校验。
- 绘制专注漫反射颜色，基础RoughMet等贴图保留。PSD层、RoughMet通道绘画及任意曲面形变包裹未实现。表面贴花与当前相机投影均可将透明图案写入UV。
- 投影和笔刷遮挡检测使用几何，不计算透明贴图孔洞；因此透明舱盖等几何可能挡住后方投影。
- 全分辨率PNG嵌入GLB可能产生很大文件。F14示例约1.02GB，保留精度并与预览mip预算分开。找不到的原始贴图列入导出报告，不用替代图片掩盖缺失。
- 发行包不包含DCS资源、测试程序或调试器；旧Python代码仅保留作开发对照，原生程序不调用Python或Qt。
